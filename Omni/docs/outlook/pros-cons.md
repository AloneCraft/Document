# 良いところ・苦手なところ

## 良いところ

| 良いところ | 中身 |
|---|---|
| **範囲と精度が桁違い** | `double`（約 16 桁）は、宇宙の端では 1 目盛りが約 1 億 km になる。Logical は**どこでも** 1.26×10⁻²⁹ m |
| **カメラ 1 台・奥行き 1 枚** | カメラを重ねないので、影・前後関係・半透明・ポスト処理が 1 回の描画でつながる。つなぎ目が最初から無い |
| **今ある URP の資産が使える** | Lit、Shader Graph、VFX Graph、Terrain などを変換器が Radial 用に作り直し、元へも戻せる |
| **Editor でそのまま作れる** | Scene View で、どの大きさでも動かす・選ぶ・置くができる |
| **間違った絵を出さない仕組みごと配る** | 対応外は止める検査、変換の保証の表、自分で確かめる検証 Hub |
| **ブラウザーで動く** | デモが WebGPU で動くので、買う前に試せる |

!!! note
    これらは開発文書（『Omni ロードマップ・戦略』の案）での自己評価です。外部の第三者が比べた結果ではありません。

## 苦手なところ

| 苦手なところ | 中身 | 開発文書での手当て（案） |
|---|---|---|
| **Unity の版の変化に弱い** | 変換器が URP のシェーダーの**文字**を探して書き換えている。URP が変わると変換が止まる。**最大のリスク** | 0.2 で、Unity の版ごとに変換器を分ける |
| 入れただけでは動かない | 切り替えの操作と時間が要る（最初は約 112 秒の例） | 0.2 で速さを改善 |
| 画面の点ごとの重さが未計測 | 奥行きを点ごとに書くので、標準より重いはず。まだ測っていない | 0.2 で測って公表 |
| 遊びの仕組みが無い | 物理・当たり判定は Unity のまま（`float` の範囲） | 1.0 のあと |
| 見た目の部品が少ない | 惑星・大気・星の既製品は少ない。今はデモが見本 | 0.3 で天体の部品を製品にする |
| 実績が少ない | 新しく、作り手も少人数 | デモと検証 Hub で確かめられるようにする |
| モバイルで動かない | Shader Model 4.5 が必要 | 1.0 のあと |
| 止まる場面が多い | 「対応していません」と止まることが、似た道具より多い | 欠点ではなく、正しさを守るための性質として説明する |

## 似た道具との違い（考え方の比較）

| やり方 | 代表例 | 得意 | Omni から見た違い |
|---|---|---|---|
| 原点をずらす | Asset Store の宇宙向けアセット | 実績と見た目の部品が豊富 | 位置の震えは直るが、奥行きは別の工夫（カメラの重ね合わせなど）が要る |
| 倍精度＋原点ずらし | 地球の実データ向けの道具 | 実在の地球のデータを流せる | 地球より外は対象外 |
| エンジンごと倍精度 | Unreal Engine 5 の大きな世界の座標 | 物理もシェーダーもそのまま動く | Unity ではない。範囲は太陽系の内側まで（地球と太陽の距離に届かない） |
| 細かい形の自動の粗さ調整 | Nanite 風の仕組み | ポリゴンの量の問題を解く | 大きさの問題は解かない |

## どんな人に向くか

**向く人**

- Unity で宇宙・惑星のゲームやシミュレーションを作りたい人。
- 科学の可視化、教育、プラネタリウム、映像など、**大きさの違いそのもの**を見せたい人。
- すでに URP のプロジェクトと素材を持っていて、別のエンジンへ乗り換えたくない人。

**ほかの道具の方が合う人**

- 実在の地球のデータだけを扱う人。
- 数十 km くらいの普通のオープンワールド（原点をずらすだけで足りる）。
- 写真のような見た目を最優先する人。
- モバイル、HDRP、Built-in のパイプラインを使う人。
